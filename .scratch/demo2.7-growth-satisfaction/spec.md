# Demo2.7 小岛成长、饮品店装修与每日满意度

**Status:** ready-for-agent

## Problem Statement

玩家已经能够种植草莓、制作饮品、处理顾客订单，并通过六个室外吧台离线售卖饮品，但现有经验与等级只提供基础数值变化，没有形成清晰、可持续的成长循环。玩家无法从小岛升级中逐级获得新作物与固定配方，也无法主动花金币装修饮品店来提高顾客队列容量、单吧台上架容量和经营效率。

同时，玩家缺少一天经营成果的反馈。当前系统不会按顾客订单的交付与拒绝结果计算每日满意度，也没有最低交付份数、五档礼品、自动发放通知和最近一个月记录。因此玩家既看不到当天经营目标，也无法从稳定履约中获得日常奖励。

## Solution

Demo2.7 建立一条以玩家经验驱动的小岛成长线。小岛等级按累计玩家经验自动提升，一级至十级采用可配置阈值；一次结算跨越多个等级时，系统按等级顺序幂等发放每一级固定配置的作物种植权与等级赠送配方。作物种植权与配方资格均为永久资格，不因材料、店铺或生产建筑尚未解锁而延迟发放。

饮品店建立独立的一级至十级装修成长线。小岛等级只开放装修资格，玩家仍需按顺序花费配置金币主动装修。饮品店等级决定顾客队列容量、单吧台每批上架上限、吧台新批次的销售间隔、顾客到店间隔和品类或配方能力；六个室外吧台从一级开始始终全部可用。

系统按北京时间自然日统计每日满意度。满意度等于当天成功交付的顾客订单数除以当天全部已关闭顾客订单数；奖励资格还要求当天实际交付的饮品总份数不少于二十份。达到百分之六十至百分之一百时分别获得五档可配置礼品。上一日结果在玩家后续登录或读取满意度时幂等结算并自动发放，客户端只通知发放结果，不要求手动领取。玩家可通过饮品店的小入口查看今日进度、规则和最近一个月内有实际订单处理记录的日结历史。

## User Stories

1. As a 玩家, I want 小岛等级由累计玩家经验自动提升, so that 所有经营行为汇入同一条长期成长线
2. As a 玩家, I want 看见当前累计玩家经验和下一级阈值, so that 我知道距离升级还有多远
3. As a 玩家, I want 小岛等级只升不降, so that 后台调整阈值不会收回已经取得的成长
4. As a 玩家, I want 一次获得大量经验时可以连续提升多个等级, so that 经验不会被截断或丢失
5. As a 玩家, I want 连续升级时逐级看见奖励, so that 我能理解每一级获得了什么
6. As a 玩家, I want 每个小岛等级固定获得一种作物种植权, so that 新作物按明确节奏开放
7. As a 玩家, I want 作物种植权永久有效且种植时不消耗种子, so that 我不会因为种子耗尽而失去种植能力
8. As a 玩家, I want 每个小岛等级固定获得一个等级赠送配方, so that 升级奖励可预期而不是随机
9. As a 玩家, I want 等级赠送配方不能从其他渠道提前获得, so that 小岛升级保持独特价值
10. As a 玩家, I want 配方在缺少材料或店铺能力时仍立即归我所有, so that 我能提前看到后续经营目标
11. As a 玩家, I want 缺少材料或店铺能力的配方显示获取引导, so that 我知道为什么暂时不能制作
12. As a 现有玩家, I want 上线后自动补齐当前等级及以下的固定奖励, so that 老账号不会遗漏新增成长内容
13. As a 玩家, I want 收获作物时获得配置的玩家经验, so that 种植可以推动小岛成长
14. As a 玩家, I want 顾客订单按实际交付份数获得经验, so that 完成更大的订单有相应成长
15. As a 玩家, I want 吧台仅对已经售出的饮品结算经验, so that 上架或退回库存不会凭空产生经验
16. As a 玩家, I want 单纯制作、上架和拒单不产生玩家经验, so that 经验只来自真实经营成果
17. As a 玩家, I want 小岛等级只开放饮品店装修资格, so that 我仍需安排金币并主动选择装修
18. As a 玩家, I want 饮品店必须逐级装修, so that 我不能跳过中间成长阶段
19. As a 玩家, I want 装修前看见所需小岛等级、金币和本级收益, so that 我能做出清楚的消费决定
20. As a 玩家, I want 金币不足时看见缺少数量, so that 我知道还需经营多久
21. As a 玩家, I want 一级饮品店就能使用全部六个室外吧台, so that 地图上的六套桌椅始终有实际用途
22. As a 玩家, I want 单吧台每批上架上限从十份逐步提升到二十份, so that 装修可以减少频繁补货
23. As a 玩家, I want 饮品店装修后顾客队列在指定等级扩容, so that 高等级经营可以同时服务更多顾客
24. As a 玩家, I want 顾客到店间隔只在指定等级缩短, so that 每一级有清晰而不过度叠加的收益
25. As a 玩家, I want 吧台销售间隔只在指定等级缩短, so that 销售效率提升可感知且可平衡
26. As a 玩家, I want 已经上架的吧台批次继续使用上架时的销售间隔, so that 装修不会改变已经承诺的倒计时
27. As a 玩家, I want 已经开始的下一位顾客倒计时继续完成, so that 装修不会让到店进度突然重置
28. As a 玩家, I want 饮品店五级开放冰淇淋制作能力, so that 新品类与店铺成长形成联系
29. As a 玩家, I want 今日满意度按已交付订单占全部已关闭订单的比例计算, so that 我能理解拒单对经营评价的影响
30. As a 玩家, I want 排队中尚未处理的订单不进入满意度, so that 未作决定的订单不会提前降低评价
31. As a 玩家, I want 满意度按订单交付或拒绝发生的北京时间日期归属, so that 跨日订单有明确的统计日期
32. As a 玩家, I want 今日面板同时显示交付订单数、拒单数、交付总份数和预计档位, so that 我能及时调整当天经营
33. As a 玩家, I want 至少交付二十份后才有满意度礼品资格, so that 少量订单不能轻易获得日常奖励
34. As a 玩家, I want 百分之六十、七十、八十、九十和一百对应五档礼品, so that 更高满意度有连续的奖励目标
35. As a 玩家, I want 礼品在后续登录时自动发放, so that 我不需要记得手动领取
36. As a 玩家, I want 登录时看见自动发放的礼品结果, so that 我知道背包或余额为何发生变化
37. As a 玩家, I want 多日未登录时所有符合条件的历史礼品都能补发, so that 离线不会导致奖励过期
38. As a 玩家, I want 最近一个月记录直接显示在满意度面板, so that 我能快速回顾近期经营
39. As a 玩家, I want 没有处理任何订单的日期不出现在历史中, so that 记录不会被大量空白日期淹没
40. As a 玩家, I want 通过一个小规则按钮查看满意度公式与档位, so that 主界面保持简洁但规则仍然可查
41. As a 运营维护者, I want 等级、装修和礼品数值保存在配置表, so that 以后可以由管理后台调整而无需改业务代码
42. As a 运营维护者, I want 历史日结保存当日礼品快照, so that 以后调配置不会改写已经结算的结果
43. As a 系统维护者, I want 所有成长、装修、日结和发奖写操作使用 JWT 玩家身份, so that 客户端不能伪造其他玩家
44. As a 系统维护者, I want 连续升级、装修和满意度发奖具备重复与并发安全, so that 重试不会重复扣金币或发奖励

## Implementation Decisions

- 玩家经验改为累计值，不在升级时扣减。小岛等级阈值使用累计经验配置：一级 `0`、二级 `100`、三级 `250`、四级 `450`、五级 `700`、六级 `1000`、七级 `1400`、八级 `1900`、九级 `2500`、十级 `3200`。
- 小岛等级只升不降。配置阈值提高时不降低现有等级；经验继续累计。一次结算跨越多个阈值时，在同一事务中按升序完成全部升级。
- 现有玩家迁移时保留当前等级、金币和已取得资格；将旧的等级内剩余经验转换为累计经验，并保证转换后的经验至少达到当前等级的新阈值，不允许迁移导致降级。
- 每一级奖励使用配置和玩家领取记录保证幂等。新玩家初始化领取一级奖励；现有玩家登录时补齐当前等级及以下尚未领取的奖励；并发初始化、经验结算或数据修复不得重复发放。
- 一级至十级固定奖励如下：

| 小岛等级 | 永久作物种植权 | 等级赠送配方 | 同级资格提示 |
| ---: | --- | --- | --- |
| 1 | 草莓 | 草莓汁 | 初始内容 |
| 2 | 胡萝卜 | 胡萝卜汁 | — |
| 3 | 橙子 | 橙汁 | — |
| 4 | 番茄 | 番茄汁 | — |
| 5 | 蓝莓 | 牛奶冰淇淋 | 牛棚购买资格提示 |
| 6 | 苹果 | 苹果胡萝卜汁 | — |
| 7 | 西瓜 | 西瓜牛奶冰淇淋 | — |
| 8 | 小麦 | 草莓蛋糕 | 鸡舍与蛋糕店后续能力提示 |
| 9 | 柠檬 | 柠檬牛奶冰淇淋 | — |
| 10 | 黄瓜 | 黄瓜苹果汁 | — |

- 等级赠送配方由配置逐级固定指定，不进行运行时随机，也不进入商店、抽奖或其他提前获取渠道。获得资格时不检查玩家是否拥有材料、牛棚、鸡舍或蛋糕店。
- Demo2.7 只建立上述作物的一级基础配置和永久种植权，不实现作物二至十级升级。八级草莓蛋糕只授予配方资格和缺少能力提示，不实现蛋糕制作。
- 等级赠送配方的初始材料沿用已确认配置：单作物汁使用对应作物，苹果胡萝卜汁使用苹果和胡萝卜各一份，牛奶冰淇淋使用牛奶，西瓜与柠檬牛奶冰淇淋分别使用对应水果与牛奶，草莓蛋糕使用草莓、小麦和鸡蛋，黄瓜苹果汁使用黄瓜和苹果各一份。具体数量以配置记录为准。
- 玩家经验继续由既有公开经营入口结算：收获按本轮快照发放一次收获经验；顾客订单按实际交付份数乘单份经验快照；吧台收取或下架只结算已售份数乘单份经验快照。制作、上架、拒单和未售退货不发经验。
- 饮品店等级是独立持久化状态，不积累独立经验。小岛等级只提供目标等级的装修资格，装修必须逐级进行并原子扣除金币。
- 饮品店一级至十级装修金币依次为免费初始、`500`、`1000`、`2000`、`3500`、`5500`、`8000`、`11000`、`15000`、`20000`，所需小岛等级与目标饮品店等级相同。

- 六个吧台从饮品店一级起全部可用，饮品店等级不控制吧台数量。上架接口允许玩家选择一份至当前等级单吧台上限，且不得超过背包实际库存。
- 吧台批次继续遵守 ADR 0001 与 ADR 0002：上架时锁定单份金币、玩家经验和销售间隔。装修后的销售间隔只影响新批次。
- 顾客队列首次进入时填满当前饮品店等级容量。容量扩大后不立即补满，继续按顾客到店间隔逐位补充。装修时已经开始的下一位顾客倒计时继续按旧间隔完成；该顾客到达或倒计时重新开始后采用新等级间隔。
- 饮品店状态、下一等级门槛、金币成本和收益预览通过 JWT 权威读取；装修写操作只信任 JWT 对应玩家，不接受客户端玩家编号。
- 每日满意度按北京时间 `Asia/Shanghai` 自然日和订单关闭时间归属。交付与拒绝跨日时以实际交付或拒绝发生日期计算，不以订单生成日期计算。
- 每日满意度公式为 `当天成功交付订单数 / 当天全部已关闭订单数`。排队中订单不参与；当天没有已关闭订单时满意度为零且不生成历史展示记录。
- 奖励资格除满意度外还要求当天成功交付的饮品总份数至少为二十份。份数来自订单实际交付数量，不按订单数替代。
- 初始五档礼品配置为：百分之六十、七十、八十、九十、一百，最低交付份数均为二十，对应 `100`、`200`、`300`、`400`、`500` 金币。
- 礼品档位、阈值、最低交付份数和奖励项保存在可版本化配置中。日结保存实际使用的档位与礼品快照；以后调配置只影响生效日期之后的新日结。
- 上一日及更早未结算日期在玩家后续登录或读取满意度状态时按服务器时间惰性补结。玩家多日未登录时所有符合条件的日期均可补发，不设置待发天数上限。
- 每个玩家与北京时间日期最多一个日结记录。日结记录、礼品发放、余额或背包变更在同一事务内完成，并以数据库唯一约束抵抗重复与并发请求。
- 满意度读取返回今日交付订单数、拒绝订单数、已关闭订单数、交付总份数、当前满意度、预计档位、距离资格或下一档差值，以及最近三十个北京时间自然日内有已关闭订单的日结记录。
- 客户端在饮品店提供单一的小入口。面板直接展示最近记录，在较小区域展示今日进度；规则说明由面板内的小按钮按需展开，不长期占用主界面。
- 自动发放的历史礼品在登录后以通知形式展示结果，不要求点击领取。读取历史不会再次发奖。
- 所有数值采用数据库初始化配置，为未来管理后台预留版本、生效时间和启停字段；Demo2.7 不建设后台页面或后台写接口。

## Testing Decisions

- 测试只验证玩家可观察的外部行为，不断言私有方法、内部调用次数或具体类结构。
- 服务端以真实 Spring MVC、JWT 和测试数据库 HTTP 契约作为最高公共接缝，覆盖游戏初始化、经营收益结算、饮品店读取与装修、顾客队列、吧台上架/收取/下架、满意度读取与自动发奖。
- 时间只在系统边界注入可控服务器时钟，用于验证北京时间跨日、历史补结、顾客到店倒计时和吧台销售快照；业务方法不接收客户端时间。
- 数据库约束与事务通过重复、并发和多玩家隔离场景验证，重点覆盖连续升级奖励、装修扣金币、满意度日结和自动发奖幂等。
- 既有收获、顾客订单和吧台测试作为经验来源的先例；既有饮品店 JWT HTTP 测试与吧台 JWT HTTP 测试作为公开契约先例。
- 客户端通过完整页面脚本行为测试验证等级进度、装修预览与确认、操作后刷新、满意度入口、规则按钮、今日进度、最近记录和登录礼品通知。
- 客户端还需运行 TypeScript 检查、现有页面回归测试和所有页面内联脚本语法检查。
- 数据库迁移同时覆盖正式数据库脚本与测试数据库结构；完成时进行与风险相称的真实迁移、真实 JWT HTTP 和页面交互验证。

## Out of Scope

- 作物二至十级升级、作物升级赠送的五十个配方和种子商店属于 Demo2.8。
- 牛棚、奶牛、牛奶生产、鸡舍、鸡和鸡蛋生产属于 Demo2.9；Demo2.7 只允许相关材料不足提示和后续资格引导。
- 蛋糕店、蛋糕制作、两个蛋糕架及蛋糕销售属于 Demo2.10；八级只发放草莓蛋糕配方资格。
- 独立运营后台、后台账号权限、审核、发布和回滚页面不在本期；本期只有可维护的数据库配置和初始化数据。
- 顾客等待时限、顾客满意度动画、顾客 NPC、店铺室内场景、礼品手动领取和永久历史查询不在本期。
- 不增加吧台数量，不改变地图已确认的饮品店小屋外左三右三布局。
- 不实现十级以上的小岛或饮品店成长。
