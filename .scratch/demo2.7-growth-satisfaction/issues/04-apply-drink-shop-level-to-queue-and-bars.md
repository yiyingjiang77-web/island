# 04 — 将饮品店等级应用到顾客队列与吧台

**What to build:** 使用当前饮品店等级配置驱动顾客队列容量、顾客到店间隔、单吧台每批上架上限和新批次销售间隔，替换现有固定数值，同时保留既有批次收益与间隔快照。

**Blocked by:** 03 — 建立饮品店一级至十级装修

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 先通过既有顾客队列和吧台 JWT HTTP 接缝写出等级差异的失败测试，再替换固定数值
- [ ] 一级至十级顾客队列容量依次为 5、6、6、6、6、6、7、7、7、7
- [ ] 一级至十级单吧台每批上限依次为 10、11、12、13、14、16、17、18、19、20
- [ ] 一级至十级新批次销售间隔依次为 300、300、285、285、285、285、285、285、270、270 秒
- [ ] 一级至十级顾客到店间隔依次为 120、120、120、120、120、105、105、105、105、105 秒
- [ ] 六个吧台始终全部可用，饮品店等级不减少或增加吧台数量
- [ ] 玩家可选择上架一份至当前单吧台上限，且不能超过背包实际库存
- [ ] 上架时锁定当前等级销售间隔，装修不改变已经上架批次的销售速度或倒计时
- [ ] 顾客首次进入时立即填满当前容量
- [ ] 队列扩容后不立即补满，而是按当前顾客到店间隔逐位补充
- [ ] 装修时已经开始的下一位顾客倒计时继续完成；下一次倒计时采用新间隔
- [ ] 队列满员时停止到店计时，出现空位后按当前配置重新计时
- [ ] 后台将容量调低时不强制删除现有顾客，在队列回落到新上限前不再补充
- [ ] 读取接口返回当前等级实际采用的容量、上架上限、销售间隔和到店间隔
- [ ] 测试覆盖一级、关键变化等级、十级、装修前后旧/新批次、在途到店倒计时、离线补充和多玩家隔离
