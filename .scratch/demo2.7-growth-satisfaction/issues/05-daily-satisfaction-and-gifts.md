# 05 — 结算每日满意度与五档自动礼品

**What to build:** 按北京时间和顾客订单关闭结果统计今日满意度与交付总份数，建立五档可配置礼品、最近一个月日结记录和登录后自动补结发放。历史日结保存实际使用的礼品快照。

**Blocked by:** 04 — 将饮品店等级应用到顾客队列与吧台

**Status:** resolved

## Acceptance criteria

- [ ] 先以可控服务器时钟通过 JWT 顾客订单与满意度读取 HTTP 接缝写出失败测试，再实现日结
- [ ] 每日满意度按当天成功交付订单数除以当天全部已关闭订单数计算
- [ ] 直接从背包交付和现场制作并交付都计为成功交付
- [ ] 暂时没货计为已关闭拒绝订单，排队中订单不参与
- [ ] 订单按实际交付或拒绝的北京时间关闭日期归属，不按生成日期归属
- [ ] 今日状态返回交付订单数、拒绝订单数、已关闭订单数、交付总份数、满意度和预计档位
- [ ] 礼品资格要求当日交付总份数至少二十份
- [ ] 初始五档为 60%、70%、80%、90%、100%，对应 100、200、300、400、500 金币
- [ ] 满意度达标但交付不足二十份时不发礼品，并返回距离资格还差的份数
- [ ] 达到资格后只发当日最高满足档位，不叠加低档礼品
- [ ] 当天没有已关闭订单时满意度为零，不生成历史展示记录，也不发礼品
- [ ] 上一日及更早日期在登录或满意度读取时自动补结，不要求玩家手动领取
- [ ] 多日未登录时补结所有有关闭订单的日期，不限制累计天数
- [ ] 日结保存满意度、订单计数、交付总份数、档位和礼品快照
- [ ] 配置变更只影响生效日期之后的新日结，不改写历史记录
- [ ] 每个玩家与北京时间日期最多一条日结，日结、礼品入账和发放状态在同一事务完成
- [ ] 重复、并发登录或读取不会重复发放礼品
- [ ] 最近记录只返回最近三十个北京时间自然日内有已关闭订单的日期
- [ ] 所有读取和发奖只使用 JWT 玩家身份并保持玩家隔离
- [ ] 测试覆盖 59/60/69/70/79/80/89/90/99/100 百分比边界、19/20 份边界、北京时间跨日、多日补结、配置快照和并发发奖
