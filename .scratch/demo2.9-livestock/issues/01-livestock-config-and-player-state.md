# 01 — 建立畜牧配置、玩家状态与 JWT 读取接缝

**What to build:** 建立牛棚、鸡舍一级至十级配置、版本化生产规则、每位玩家的建筑与生产状态，以及认证后的畜牧汇总读取接口，为后续解锁、升级和惰性结算提供共同公共接缝。

**Blocked by:** None — requires Demo2.7 island-level state and Demo2.8 inventory/material prerequisites to be resolved before implementation

**Status:** resolved

## Acceptance criteria

- [ ] 牛棚和鸡舍配置与玩家进度分别持久化，配置支持版本、生效时间、启用状态和等级唯一约束
- [ ] 配置可表达所需小岛等级、升级金币、动物容量、自动赠送动物、生产周期和每轮产量
- [ ] 牛棚配置可表达一级至十级容量及单头奶牛产量，鸡舍配置可表达基础与额外鸡蛋
- [ ] 牛棚二至十级在门槛和金币未确认时默认不可升级，不在代码中发明数值
- [ ] 鸡舍一级至十级门槛、金币、容量、周期和额外鸡蛋使用已确认配置
- [ ] 数据库约束或启动校验拒绝动物容量超过八、动物数超过容量、非正周期和负产量
- [ ] 每位玩家对每种建筑最多有一个当前状态，迁移兼容已有玩家并可幂等执行
- [ ] 玩家状态可保存当前周期开始/结束边界、周期时长、动物数、每轮产量及配置版本快照
- [ ] JWT 汇总读取只返回当前玩家的牛棚与鸡舍状态、当前配置、下一等级预览和条件
- [ ] 未解锁建筑也返回购买资格、首次奖励和准确的门槛提示
- [ ] 不接受请求体或路径中的玩家编号替代 JWT 身份
- [ ] JWT HTTP 和真实数据库测试覆盖配置加载、未解锁读取、玩家隔离与无效配置
