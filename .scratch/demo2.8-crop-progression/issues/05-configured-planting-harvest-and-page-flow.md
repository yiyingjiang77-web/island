# 05 — 使用等级快照完成多作物种植收获与页面联调

**What to build:** 将十种作物、永久种植权、作物等级与六十四格土地贯穿现有种植、浇水和收获流程，并完成页面中的作物选择、成长预览、倒计时、收获反馈、升级与种子商店入口。

**Blocked by:** 02 — 作物逐级升级并发放五十条固定配方; 03 — 通过种子商店购买额外永久种植权; 04 — 配置四个农田区块并按相邻规则购买六十四格土地

**Status:** resolved

## Acceptance criteria

- [ ] 点击空土地时只列出当前玩家永久拥有或仍有效的临时作物
- [ ] 选择器展示作物名称、当前等级、成长时间、产量和单次收获经验
- [ ] 种植不扣除任何种子物品或种植权数量
- [ ] 种植时保存作物等级、成长时间、产量、收获经验和权限类型快照
- [ ] 浇水后才按服务器时间开始成熟倒计时
- [ ] 已种作物在中途升级或修改配置后仍使用原快照
- [ ] 未经过完整成长时间不能收获
- [ ] 收获数量严格使用快照且最多八份
- [ ] 收获经验按一次收获结算，不乘以产量
- [ ] 收获清空土地、增加背包、增加经验和触发小岛升级处于同一事务
- [ ] 重复或并发收获不会重复增加背包、经验或小岛奖励
- [ ] JWT 是所有土地写操作的唯一玩家身份来源
- [ ] 页面完整支持购买土地、选择作物、种植、浇水、查看倒计时和收获
- [ ] 页面提供作物成长与种子商店入口，并在操作后统一刷新权威数据
- [ ] 暂不可制作的升级配方显示缺少的种植权、材料或未来制作入口
- [ ] 蛋糕、牛奶和鸡蛋提示不会触发 Demo2.9 或 Demo2.10 的未实现请求
- [ ] 客户端不写死作物成长数值、升级价格、土地价格或奖励配方
- [ ] 完整页面脚本在 `file://` 使用父子消息时不读取跨域 frame 的 location
- [ ] 服务端真实 JWT HTTP 测试覆盖十种作物、多个等级快照、成熟边界、产量上限、玩家隔离和并发
- [ ] 客户端 TypeScript、页面行为测试和两份页面脚本检查通过
- [ ] 完成与风险相称的真实 JWT HTTP 与页面验证
