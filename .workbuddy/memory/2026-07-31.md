# 2026-07-31 工作日志

## Demo2.7 前端 Bug 修复

### Bug 1: 制作台"现场制作并交付"未与选中顾客联动
- **现象**: 点击不同顾客的订单后，"现场制作并交付"按钮显示的材料消耗来自制作台下方独立选择的配方，而非当前选中顾客订单的配方
- **根因**: `renderOrderActions()` 用 `selectedRecipe`（制作台区域独立选择的配方）取材料信息，而不是从 `customer.recipeId` 查对应配方
- **修复文件**: `FruitIslandClient/demo2.4-island.html`
- **改动**:
  1. `selectCustomerOrder()`: 选中顾客时同步将制作台 `selectedRecipe` 切到顾客订单对应配方，并调用 `renderCraftingStation()` 刷新下方制作台
  2. `renderOrderActions()`: 改为从 `craftRecipes.find(r=>r.recipeId===customer.recipeId)` 取配方和材料，而非 `selectedRecipe`
  3. 增加 `hasRecipe` 判断，配方未解锁时禁用"现场制作并交付"按钮

### Bug 2: 制作台只显示第一个材料，不显示全部材料
- **现象**: strawberry_cake 需要 草莓×2 + 小麦×2 + 鸡蛋×1，但前端只显示"草莓 ×2/份"，用户以为只需要草莓就能做
- **根因**: `renderCraftingStation()` 和 `renderOrderActions()` 都只取 `recipe.materials[0]`，没有遍历全部材料
- **修复**: 改为遍历 `recipe.materials` 全部材料，每种材料显示名称、需求量、库存和消耗量，材料不足时标红并禁用制作按钮
- **数据库确认**: `recipe_material` 表中 strawberry_cake 有 3 条记录（strawberry/wheat/egg），`maxCraftable=0`（因小麦和鸡蛋库存为 0），后端校验逻辑正确，纯前端展示问题

### Bug 3: 材料不足时"+"按钮仍可点击
- **现象**: 顾客订单的"现场制作"数量选择器，"+"按钮在材料不足时仍可点击，导致数量增加但无法制作
- **根因**: `renderOrderActions()` 中"+"按钮只检查 `orderCraftQuantity>=99`，未根据材料库存计算最大可制作份数
- **修复**: 在 `renderOrderActions()` 和 `changeOrderCraftQuantity()` 中增加 `maxCraftable` 计算（遍历配方所有材料，取 `floor(库存/单份需求)` 的最小值），"+"按钮在 `orderCraftQuantity>=maxCraftable` 时禁用

### Bug 4: 背包库存不足时"从背包完整交付"按钮仍可点击
- **现象**: 顾客订单要求交付 N 份产品，但背包库存不足 N 份时，"从背包完整交付"按钮仍可点击，点击后服务端报错
- **修复**: `renderOrderActions()` 中从 `drinkBarState.drinks` 查找 `customer.itemId` 对应的 `inventoryCount`，不足时禁用按钮并显示当前库存数
