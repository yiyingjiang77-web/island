# 果香小岛 Demo2.5 饮品店首个闭环规格

> 状态：已确认  
> 整理日期：2026-07-29  
> 当前客户端入口：`FruitIslandClient/demo2.4-island.html`  
> 领域词汇：`CONTEXT.md`

## 1. 版本目标

Demo2.5 在现有“种植 → 收获”闭环之后增加饮品店经营入口，完成：

```text
种植并收获草莓
  ↓
通过制作台批量制作草莓汁，或针对顾客订单现场制作
  ↓
完整交付顾客订单
  ↓
获得金币和玩家经验
```

本版本只实现草莓汁一个配方，但数据结构和接口不得把业务写死为草莓汁。

## 2. 本版本范围

### 2.1 包含

- 草莓汁初始永久配方。
- 最多五人的顾客队列。
- 按时间补充顾客及离线补算。
- 顾客订单随机生成。
- 使用背包成品完整交付。
- 针对订单现场制作并完整交付。
- “暂时没货”关闭订单。
- 饮品店制作台批量制作。
- 饮品售出后结算金币和玩家经验。
- 订单收益快照。

### 2.2 不包含

- 六个吧台及离线售卖。
- 每日满意度、礼品和奖励记录。
- 饮品店装修等级。
- 配方商店、限时配方任务。
- 牧场、牛奶、奶茶和冰淇淋。
- 计时制作和酿酒。

这些能力已有领域规则，但分别放入 Demo2.6、Demo2.7 和后续版本。

## 3. 草莓汁配置

| 配置项 | 数值 |
| --- | ---: |
| 输入 | 草莓 ×2 |
| 输出 | 草莓汁 ×1 |
| 制作时间 | 0 秒，立即完成 |
| 单份售出金币 | 30 |
| 单份售出玩家经验 | 5 |
| 默认订单权重 | 100 |
| 配方资格 | 初始永久解锁 |

草莓汁配方：

- 新玩家初始化时自动永久获得。
- 现有玩家进入游戏时若缺少则自动补发。
- 不进入配方商店。
- 不依赖玩家等级或饮品店等级。

制作本身不产生金币或经验；只有成品售出时才结算金币和玩家经验。

## 4. 顾客队列

### 4.1 容量与操作

- 队列最多同时存在五位顾客。
- 玩家首次进入饮品店时立即生成五位顾客。
- 五位顾客都可以直接选择和操作，不限制只能处理队首。
- 顾客完成交付或选择“暂时没货”后离开，后续顾客在界面中前移。
- 顾客没有等待期限，不会自行离开。

### 4.2 到店计时

- 队列满员时停止到店计时。
- 队列首次出现空位时，从该时刻开始两分钟倒计时。
- 倒计时结束后补充一位顾客。
- 如果仍有空位，再开始下一轮两分钟倒计时。
- 满员期间不积攒到店次数，也不在出现空位后一次性补发。
- 玩家离线期间使用相同规则补算，但最多补到五位。
- 离线不会自动拒单，也不会改变订单状态。

## 5. 订单生成

### 5.1 配方选择

- 从订单生成时玩家当前有效的配方资格中随机选择。
- 不检查玩家的材料来源、材料库存或成品库存。
- 每个配方具有可配置的订单权重，默认权重相同。
- 限时配方过期后不再生成该配方的新订单。

Demo2.5 只有草莓汁配方，因此所有订单均为草莓汁。

### 5.2 订单数量

| 数量 | 生成权重 |
| ---: | ---: |
| 1 份 | 60% |
| 2 份 | 30% |
| 3 份 | 10% |

数量权重必须配置化，不能写死在客户端。

### 5.3 收益快照

订单生成时保存：

- 单份金币快照。
- 单份玩家经验快照。

后台修改配方收益后：

- 已生成订单继续按原快照结算。
- 新生成订单使用新配置。

具体决策见 `docs/adr/0001-snapshot-drink-sale-rewards.md`。

## 6. 订单操作

每张订单提供以下操作。

### 6.1 使用背包成品交付

- 背包中的对应成品数量不少于订单数量时可用。
- 一次扣除订单要求的全部成品并完整交付。
- 不支持只交付一部分。

### 6.2 制作并交付

- 背包成品不足时，不与现场制作混合使用。
- 玩家选择的制作数量不得少于订单数量。
- 材料必须足以完成玩家选择的全部制作数量。
- 订单需要的数量立即售出。
- 超过订单数量的成品进入背包。
- Demo2.5 单次制作数量最多 99 份。

示例：

```text
订单：草莓汁 ×2
选择制作：5 份
扣除：草莓 ×10
立即售出：草莓汁 ×2
进入背包：草莓汁 ×3
获得：金币 60、玩家经验 10
```

### 6.3 暂时没货

- 当前订单关闭，顾客立即离开。
- 不扣金币。
- 不扣玩家经验。
- 不发放任何奖励。
- Demo2.5 不引入满意度结算，但订单需要保留明确的拒绝关闭结果，供 Demo2.7 使用。

## 7. 制作台

- 制作台是独立于顾客订单的入口。
- 玩家选择已拥有配方和制作数量。
- 默认制作数量为 1，单次最多 99。
- 支持减少、增加和“最大”操作。
- “最大”不得超过当前材料能够制作的数量或单次 99 份上限。
- 制作成功后，全部成品进入背包。
- 制作台不产生金币或玩家经验。

示例：

```text
选择草莓汁 ×4
扣除草莓 ×8
背包增加草莓汁 ×4
金币和经验不变
```

## 8. 结算与事务规则

以下操作必须分别在单个数据库事务中完成。

### 8.1 背包交付事务

1. 锁定并校验订单仍处于等待状态。
2. 校验玩家拥有足量成品。
3. 扣除成品。
4. 按收益快照增加金币和玩家经验。
5. 执行玩家自动升级及升级金币奖励。
6. 关闭订单。

### 8.2 制作并交付事务

1. 锁定并校验订单仍处于等待状态。
2. 校验制作数量、配方资格和材料数量。
3. 扣除全部材料。
4. 将超出订单的成品加入背包。
5. 按订单数量和收益快照增加金币与玩家经验。
6. 执行玩家自动升级及升级金币奖励。
7. 关闭订单。

### 8.3 制作台事务

1. 校验配方资格和制作数量。
2. 校验并扣除全部材料。
3. 将全部成品加入背包。

重复请求、并发点击或网络重试不能导致：

- 重复扣除材料。
- 重复增加成品。
- 重复发放金币或经验。
- 同一订单被关闭两次。

## 9. 建议数据结构

### 9.1 配方配置

在现有 `recipe_config`、`recipe_material` 基础上补足：

- 成品物品 ID。
- 制作秒数。
- 单份售出金币。
- 单份售出玩家经验。
- 订单随机权重。
- 配方品类和启用状态。

### 9.2 玩家配方资格

新增玩家配方资格记录，至少支持：

- 永久资格。
- 限时资格的开始和结束时间。
- 获得来源。

结构应参考现有作物永久资格与限时资格的分离方式，避免用背包数量表达配方权利。

### 9.3 顾客订单

现有 `customer_order` 需要补足：

- 配方 ID。
- 成品物品 ID。
- 订单数量。
- 单份金币快照。
- 单份经验快照。
- 等待、已交付、暂时没货等状态。
- 创建、关闭时间。
- 关闭原因。

### 9.4 顾客到店状态

需要为每位玩家保存下一位顾客到店时间或等价状态，以便：

- 满员时停止计时。
- 出现空位后重新开始两分钟计时。
- 登录时准确补算离线顾客。

## 10. 建议接口

```text
GET  /drink-shop
```

返回饮品店状态、顾客队列、配方、材料可制作数量和背包成品数量。

```text
POST /drink-shop/orders/{orderId}/deliver
```

使用背包成品完整交付。

```text
POST /drink-shop/orders/{orderId}/make-and-deliver
body: { "makeQuantity": 5 }
```

现场制作并完整交付，多余成品进入背包。

```text
POST /drink-shop/orders/{orderId}/out-of-stock
```

以“暂时没货”关闭订单。

```text
POST /drink-shop/craft
body: { "recipeId": "strawberry_juice", "quantity": 4 }
```

通过制作台制作，成品全部进入背包。

所有写接口必须从 JWT 获取玩家身份，不接受客户端传入 `playerId`。

## 11. 客户端交互

点击地图上的饮品店进入饮品店页面或面板，至少包含：

- 五个顾客及其订单卡片。
- 下一位顾客到店倒计时。
- 顾客订单详情。
- “背包交付”“制作并交付”“暂时没货”操作。
- 制作数量选择和材料消耗预览。
- 制作台入口。
- 配方、材料需求、当前库存和最大可制作数量。
- 操作结果提示。

订单交付或制作成功后必须刷新：

- 顾客队列。
- 背包。
- 金币。
- 玩家经验、等级和升级所需经验。

## 12. 验收标准

### 12.1 初始资格

- 新玩家自动拥有草莓汁永久配方。
- 旧账号缺少草莓汁配方时自动补发。

### 12.2 顾客队列

- 首次进入立即出现五位顾客。
- 任意顾客均可操作。
- 处理订单后不会立即补位。
- 出现空位两分钟后只补一位。
- 满员期间不积攒补位。
- 离线补算最多填到五位。
- 顾客不会因等待自动离开。

### 12.3 订单履约

- 草莓汁订单只生成 1–3 份。
- 背包成品足够时可完整交付。
- 背包成品不足时不能部分交付或与现场制作混用。
- 现场制作数量小于订单数量时拒绝。
- 现场制作足量时正确扣除材料、交付订单并保存多余成品。
- “暂时没货”关闭订单且不发放收益。

### 12.4 制作台

- 草莓 ×2 正确产出草莓汁 ×1。
- 单次制作范围为 1–99。
- 材料不足时操作失败且不产生部分扣除。
- 制作台成品全部进入背包且不发收益。

### 12.5 收益

- 每售出一份草莓汁获得 30 金币和 5 玩家经验。
- 订单多份收益线性计算。
- 玩家经验正确触发自动升级和升级金币。
- 修改配方收益后，旧订单按旧快照结算，新订单按新配置结算。

### 12.6 安全与一致性

- 所有写接口使用 JWT 玩家身份。
- 重复提交同一订单不会重复发奖。
- 并发请求不会造成负库存。
- 服务端测试、客户端 TypeScript 检查和页面脚本检查全部通过。

## 13. 后续版本边界

### Demo2.6：吧台售卖

- 六个吧台。
- 每次固定上架一种成品十份。
- 每三分钟售出一份，三十分钟售完。
- 离线销售补算。
- 未售完不能正常收取，只能下架结算。
- 下架退回未售成品并结算已售收益。
- 一键收取只处理已经全部售完的吧台。

### Demo2.7：成长与满意度

- 饮品店金币装修升级，无独立经验。
- 玩家等级固定赠送配方。
- 配方商店金币购买，并预留元宝等渠道。
- 每日满意度按北京时间零点结算。
- 满意度等于已交付订单数除以全部已关闭订单数；无订单时为零。
- 每日至少交付 20 单且满意度达到 60% 才有礼品。
- 60%、70%、80%、90%、100% 对应五档可配置礼品。
- 登录时自动发放，弹窗只通知。
- 保存并展示最近一个月的满意度奖励记录。

### 后续版本

- 牧场、奶牛、母鸡及动物产物。
- 饮品店五级解锁首个冰淇淋配方。
- 冰淇淋必须消耗牛奶等材料，但不直接检查牧场解锁状态。
- 奶茶等奶制饮品。
- 计时制作、顾客等待和酿酒。
