# Demo2.6 饮品店室外吧台售卖

**Status:** resolved

## Problem Statement

玩家已经可以制作饮品并完成顾客订单，但背包中的成品没有持续经营用途。饮品店小屋外也缺少能够表达经营状态的可交互设施。玩家需要把成品上架到室外吧台，让饮品随时间售出，并在稍后回来结算收益。

## Solution

在饮品店小屋左侧和右侧各布置三套桌椅，共六个室外吧台。玩家可以从统一入口查看全部吧台，也可以直接点击地图上的桌椅操作具体吧台。

空吧台可以上架同一种成品饮品一至十份。库存达到十份时上架十份；库存只有一至九份时，玩家可以全部直接上架或跳转到普通制作台。每个批次独立保存饮品、数量、单份金币、单份玩家经验和单份销售间隔快照。草莓汁默认每三分钟售出一份，第一份必须经过完整三分钟才售出；服务端以时间戳惰性补算在线和离线进度。

未售完批次可以随时下架：未售成品退回背包，已售部分立即结算。售罄批次继续占用吧台，直到玩家单独收取或一键收取；未售罄吧台不会被一键收取影响。

## User Stories

1. As a 玩家, I want 六个吧台默认全部开放, so that 我可以同时经营多个批次。
2. As a 玩家, I want 在小屋左侧和右侧各看到三套桌椅, so that 吧台与地图空间自然结合。
3. As a 玩家, I want 通过统一的吧台入口查看六个吧台, so that 主界面不会铺满经营详情。
4. As a 玩家, I want 直接点击地图上的桌椅, so that 我可以快速操作具体吧台。
5. As a 玩家, I want 空桌、售卖中和待收取使用不同视觉状态, so that 我不打开详情也能判断经营状态。
6. As a 玩家, I want 具体数字只在点击后显示, so that 地图保持简洁。
7. As a 玩家, I want 同一种饮品同时上架到多个吧台, so that 足量库存可以并行销售。
8. As a 玩家, I want 库存达到十份时一次上架十份, so that 满批次操作简单。
9. As a 玩家, I want 库存只有一至九份时直接全部上架, so that 少量成品也能参与经营。
10. As a 玩家, I want 库存不足时跳转普通制作台, so that 我可以自行选择配方并从默认一份开始制作。
11. As a 玩家, I want 没有任何成品时只看到去制作入口, so that 不会执行无意义的零数量上架。
12. As a 玩家, I want 上架前看到单份和整批预计收益, so that 我知道该批次的经营价值。
13. As a 玩家, I want 上架后经过完整三分钟才售出第一份, so that 倒计时行为可预测。
14. As a 玩家, I want 每三分钟售出一份, so that 十份满批次在三十分钟售罄。
15. As a 玩家, I want 每个吧台独立计时, so that 并行批次互不影响。
16. As a 玩家, I want 离线期间继续销售, so that 离开游戏不会丢失经营进度。
17. As a 玩家, I want 返回时看到补算后的剩余数量和待收收益, so that 状态与真实经过时间一致。
18. As a 玩家, I want 未售完时随时下架, so that 我可以更换经营安排。
19. As a 玩家, I want 下架时取回全部未售成品, so that 未售库存不会丢失。
20. As a 玩家, I want 下架时结算已经售出的部分, so that 已完成销售得到应有收益。
21. As a 玩家, I want 一份都没卖出时下架并取回全部成品, so that 取消批次没有额外损失。
22. As a 玩家, I want 售罄后单独收取一个吧台, so that 我可以逐个处理收益。
23. As a 玩家, I want 一键收取所有已售罄吧台, so that 多个完成批次可以快速结算。
24. As a 玩家, I want 一键收取不影响未售罄吧台, so that 仍在销售的批次继续经营。
25. As a 玩家, I want 售罄未收取的吧台继续被占用, so that 新批次不会覆盖待收收益。
26. As a 玩家, I want 收取时统一结算金币、经验和升级奖励, so that 玩家成长结果准确且提示集中。
27. As a 玩家, I want 配置变化不改变已上架批次, so that 已看到的收益和售罄时间保持稳定。
28. As a 玩家, I want 登录时只看到可收取数量角标而非强制弹窗, so that 我可以自行决定何时处理吧台。

## Implementation Decisions

- 饮品店固定拥有六个默认开放的室外吧台，地图布局为小屋左侧三套、右侧三套，中间保留入口和通道。
- 地图桌椅可直接点击；统一入口打开六个吧台总览，并显示可收取吧台数量角标。
- 地图只展示空闲、售卖中、售罄待收取三种视觉状态，不直接展示数字详情。
- 每个吧台同一时间最多有一个活动批次；不同吧台允许上架同一种饮品。
- 每批只能包含同一种成品饮品，上架数量为一至十份。
- 当目标饮品库存不少于十份时，上架十份；库存为一至九份时，“直接上架”会将当前库存全部上架。
- 库存不足十份时同时提供“去制作”；它只打开现有普通制作台，不预选配方，制作数量保持默认一份。
- 库存为零时不能上架，只提供去制作入口。
- 草莓汁默认销售间隔为 180 秒/份；销售间隔必须配置化。
- 第一份在上架满 180 秒后售出。已售数量为经过秒数除以间隔快照向下取整，并限制在上架数量以内。
- 不为每个玩家创建后台定时任务。服务端在读取、下架和收取等公共操作时按服务器时间惰性补算。
- 批次上架时保存单份金币、单份玩家经验和销售间隔快照。
- 未售完不能正常收取；只能下架。下架退回未售成品并结算已售收益。
- 售罄批次停止销售并占用吧台，直到单独收取或一键收取。
- 一键收取只处理调用时已经售罄的批次，汇总收益后统一执行玩家升级；其他批次不变。
- 所有写接口从 JWT 获取玩家身份，不接受客户端玩家 ID。
- 上架、下架、单独收取和一键收取必须各自在单个数据库事务中完成。
- 吧台、批次、背包和玩家行在并发写操作中使用稳定锁顺序；重复请求不得重复扣货、退货或发奖。
- 状态至少区分空闲、售卖中、售罄待收取和已关闭批次；保留批次历史，不能通过覆盖当前行丢失结算依据。
- API 提供读取六个吧台、上架、下架、单独收取和一键收取能力。

## Testing Decisions

- 主要公共测试接缝为 JWT HTTP 契约；通过响应及后续读取观察吧台、背包、金币、经验和等级，不测试私有方法。
- 时间与数据库是系统边界。测试使用可控制时钟验证 179 秒、180 秒、多轮销售、三十分钟售罄和长时间离线补算。
- 上架测试覆盖库存 0、1、9、10 和超过 10 份，同饮品多吧台，以及原子扣减失败。
- 下架测试覆盖零售出、部分售出、刚好到销售边界和售罄竞态。
- 收取测试覆盖单独收取、一键收取、混合完成状态、升级奖励、重复请求和并发请求。
- 收益和销售间隔快照测试使用上架后修改配置的场景，验证旧批次不变、新批次使用新配置。
- 客户端测试观察统一入口、桌椅视觉状态、详情面板、按钮可用性、跳转普通制作台和操作后的刷新结果。
- 复用现有饮品店控制器 JWT 测试、可控制时钟、库存原子扣减和玩家锁定收益结算作为先例。
- 完成后运行完整服务端测试、客户端 TypeScript、客户端回归测试和两份页面脚本检查，并进行真实 JWT HTTP 与页面验证。

## Out of Scope

- 饮品店小屋室内场景。
- 玩家角色在小屋内移动。
- 单个顾客 NPC 的到店、入座、喝饮品和离开动画。
- 自动收取收益。
- 自动补货或售卖中途补货。
- 吧台等级、玩家等级或饮品店等级解锁。
- 饮品店装修等级、配方商店、满意度、每日礼品和 Demo2.7 能力。
- 后台扫描所有玩家的周期性销售任务。

## Further Notes

- 本规格将早期“每批固定十份”更新为“每批最多十份”；一至九份小批次是访谈确认的正式规则。
- 服务端时间是销售进度的唯一权威。客户端倒计时只用于展示，不能决定售出数量或收益。
- 已上架批次的可预测性优先于后台配置即时生效，具体销售间隔快照决策见 ADR 0002。
